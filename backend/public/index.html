API de Produtos

Uma API REST para você praticar fetch() com todos os métodos HTTP: GET, POST, PUT, PATCH e DELETE, cadastrando, listando, editando e apagando produtos.

Cada aluno tem o seu próprio espaço. Você escolhe um código de aluno e ele vai na URL. Os produtos que você criar com o seu código só aparecem para quem usar o mesmo código.

URL base: /api/

Digite o seu código no campo Seu código, no topo da página. Os exemplos são atualizados automaticamente.

  • Todas as requisições e respostas usam JSON.
  • A API aceita requisições de qualquer origem (CORS liberado). Funciona com o HTML aberto direto do computador ou pelo Live Server.
  • O código do aluno tem de 3 a 30 caracteres: letras minúsculas, números, - ou _. Ex.: maria-silva, joao_2b.
  • Prefere testar clicando? Abra o Swagger: ele lista todas as rotas e deixa você enviar requisições direto pelo navegador. A especificação OpenAPI fica em /openapi.json.
Atenção: os dados são públicos para quem souber o seu código. Não cadastre informações reais ou pessoais. Use dados inventados.

Primeiros passos

  1. Escolha o seu código de aluno e guarde a URL base numa constante no seu script.js:

    const API = '/api/';

  2. Insira alguns produtos de exemplo para já ter o que mostrar na tela (rode uma vez só, no console do navegador ou na seção Experimente):

    await fetch(`${API}/exemplos`, { method: 'POST' });

  3. Abra no navegador e veja o JSON dos seus produtos:

    /api//produtos

  4. Agora é com você: use fetch() para listar, criar, editar e apagar. Veja os exemplos.

Exemplos com fetch

GET Listar

const API = '/api/';

async function listarProdutos() {
  const resposta = await fetch(`${API}/produtos`);
  const produtos = await resposta.json(); // array de objetos

  produtos.forEach((produto) => {
    console.log(produto.id, produto.nome, produto.preco);
  });
}

A mesma coisa usando .then():

fetch(`${API}/produtos`)
  .then((resposta) => resposta.json())
  .then((produtos) => console.log(produtos));

GET Buscar um produto

const resposta = await fetch(`${API}/produtos/1`);

if (resposta.status === 404) {
  console.log('Produto não existe');
} else {
  const produto = await resposta.json();
  console.log(produto.nome);
}

POST Criar

const novoProduto = {
  nome: 'Teclado mecânico',
  preco: 249.9,
  estoque: 10,
  categoria: 'Periféricos',
};

const resposta = await fetch(`${API}/produtos`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(novoProduto),
});

const criado = await resposta.json();
console.log(resposta.status); // 201
console.log(criado.id);       // id gerado pela API

PUT Substituir

Envie o produto completo. Campos que ficarem de fora voltam ao valor padrão.

await fetch(`${API}/produtos/1`, {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    nome: 'Teclado mecânico RGB',
    descricao: 'Switch vermelho, ABNT2',
    preco: 299.9,
    estoque: 8,
    categoria: 'Periféricos',
    ativo: true,
  }),
});

PATCH Alterar alguns campos

// muda só o estoque do produto 1, sem mexer no resto
const resposta = await fetch(`${API}/produtos/1`, {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ estoque: 0 }),
});
const atualizado = await resposta.json();

DELETE Apagar

const resposta = await fetch(`${API}/produtos/1`, { method: 'DELETE' });

if (resposta.status === 204) {
  console.log('Apagado!');
  // 204 = sem corpo. NÃO chame resposta.json() aqui.
}

Tratando erros

O fetch só lança erro quando não consegue falar com o servidor. Respostas como 400 e 404 chegam normalmente, por isso confira resposta.ok. Toda resposta de erro tem a propriedade erro com uma mensagem.

async function criarProduto(dados) {
  try {
    const resposta = await fetch(`${API}/produtos`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(dados),
    });
    const corpo = await resposta.json();

    if (!resposta.ok) {
      // ex.: { erro: 'Dados inválidos', detalhes: { nome: 'Campo obrigatório' } }
      alert(corpo.erro);
      console.log(corpo.detalhes);
      return;
    }

    console.log('Criado:', corpo);
  } catch (erro) {
    alert('Não foi possível conectar com a API');
  }
}

Filtros, busca e paginação

A listagem (GET /api/{aluno}/produtos) aceita parâmetros na URL. Dá para combinar vários com &.

ParâmetroExemploO que faz
nome do campo?ativo=true
?categoria=cabos		Filtra pelo valor exato. Texto ignora maiúsculas e minúsculas. Repita o parâmetro para aceitar mais de um valor: ?categoria=cabos&categoria=monitores
q?q=tecladoBusca o texto em parte do nome, da descricao ou da categoria
ordenar?ordenar=precoOrdena por um campo (padrão: id). Também aceita criadoEm e atualizadoEm
ordem?ordem=descasc (crescente, padrão) ou desc (decrescente)
limite?limite=10Quantidade máxima de produtos na resposta
pagina?limite=10&pagina=2Página desejada (começa em 1). Use junto com limite
atraso?atraso=2000A API espera esse tempo em milissegundos antes de responder (máx. 5000). Funciona em qualquer rota. Use para testar a sua tela de “carregando...”

A listagem sempre devolve um array. O total de produtos encontrados (sem contar a paginação) vem no header X-Total-Count:

const resposta = await fetch(`${API}/produtos?ativo=true&ordenar=preco&ordem=desc&limite=5&pagina=1`);
const produtos = await resposta.json();
const total = Number(resposta.headers.get('X-Total-Count'));

console.log(`Mostrando ${produtos.length} de ${total} produtos`);

Montando a URL a partir de um formulário de filtros:

const parametros = new URLSearchParams();
parametros.set('q', campoBusca.value);
parametros.set('ordenar', 'nome');

const resposta = await fetch(`${API}/produtos?${parametros}`);

Toda resposta de erro tem este formato. detalhes só aparece quando há algo a explicar por campo:

{
  "erro": "Dados inválidos",
  "detalhes": {
    "nome": "Campo obrigatório",
    "preco": "Deve ser um número (recebido: o texto \"19.90\"). Dica: converta com Number(valor)",
    "ativo": "Deve ser true ou false, sem aspas (recebido: o texto \"true\")"
  }
}

Erros comuns

415: “Envie o corpo em JSON com o header Content-Type: application/json”
Faltou headers: { 'Content-Type': 'application/json' } no fetch.
400: “Deve ser um número (recebido: o texto "19.90")”
O value de um <input> é sempre texto, mesmo com type="number". Converta antes de enviar: Number(input.value).
400: “Deve ser true ou false”
Para checkbox, use input.checked (que já é true/false), e não input.value.
400: “Campo desconhecido”
O nome do campo está errado. Os nomes não têm acento: nome, descricao, preco, estoque, categoria, ativo.
SyntaxError: Unexpected end of JSON input
Você chamou resposta.json() numa resposta 204 (DELETE), que não tem corpo.
404 com um id que existe
Confira o código do aluno na URL. Cada código tem os seus próprios produtos.
“Failed to fetch” ou erro de CORS no console
Geralmente é a URL errada (confira https:// e o endereço) ou a internet caiu. A API aceita qualquer origem.

Limites

  • Até 200 produtos para cada código de aluno.
  • Até 300 requisições por minuto para cada código de aluno.
  • Corpo da requisição de até 10 KB.
  • Parâmetro atraso de até 5000 ms.

Parte 2: Autenticação

Na parte 2, ninguém acessa os seus produtos só por saber o seu código. O professor cadastra você com um usuário e uma senha. Você faz login e recebe um token. O token funciona como a sua "chave" e vai no header Authorization de toda requisição.

Como funciona o token

  • Vale por 24 horas.
  • Cada usuário tem um token por vez: fazer login de novo gera outro, e o anterior para de funcionar.
  • Vai no header assim: Authorization: Bearer SEU_TOKEN (a palavra Bearer, um espaço e o token).
  • Os produtos de /privado ficam separados dos de /api/{aluno} da parte 1.

Passo a passo

  1. Pegue com o professor o seu usuário e a sua senha.

  2. Faça login com POST /auth/login e guarde o token que vem na resposta.

  3. Use as rotas /privado/... enviando o header Authorization.

  4. Se receber 401, o token expirou ou foi trocado: faça login de novo.

POST Login e guardar o token

const BASE = '';

async function login(usuario, senha) {
  const resposta = await fetch(`${BASE}/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ usuario, senha }),
  });
  const dados = await resposta.json();
  if (!resposta.ok) throw new Error(dados.erro); // 401: usuário ou senha incorretos

  // Guarda o token para não precisar logar de novo a cada recarregamento da página
  localStorage.setItem('token', dados.token);
  return dados;
}

GET Usar o token

async function listarProdutos() {
  const token = localStorage.getItem('token');
  const resposta = await fetch(`${BASE}/privado/produtos`, {
    headers: { Authorization: `Bearer ${token}` },
  });

  if (resposta.status === 401) {
    // Token ausente, expirado ou trocado: volte para a tela de login
    localStorage.removeItem('token');
    alert('Sua sessão expirou. Faça login de novo.');
    return [];
  }
  return resposta.json();
}

POST Criar com token

Quando a requisição tem corpo JSON, envie os dois headers juntos:

await fetch(`${BASE}/privado/produtos`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${localStorage.getItem('token')}`,
  },
  body: JSON.stringify({ nome: 'Mouse', preco: 49.9 }),
});

POST Sair

async function logout() {
  await fetch(`${BASE}/auth/logout`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${localStorage.getItem('token')}` },
  });
  localStorage.removeItem('token');
}

Erros comuns da parte 2

401: “Envie o token no header Authorization: Bearer <token>”
Faltou o header Authorization no fetch.
401: “Header Authorization mal formatado”
Confira se escreveu Bearer, um espaço e o token: `Bearer ${token}`.
401: “Token inválido. Ele pode ter sido substituído...”
Você (ou outra aba) fez login de novo, e o token antigo parou de valer: use o mais recente. Também acontece quando o token é null porque ele não foi salvo no login.
401: “Token expirado”
Passou o prazo de validade. Faça login de novo.
401: “Usuário ou senha incorretos”
No login, o usuário não existe ou a senha está errada. O usuário é sempre em letras minúsculas.
403: “Sua conta está inativa”
O professor desativou a sua conta. Fale com ele.

No Swagger: faça POST /auth/login, copie o token, clique em Authorize no topo e cole. A partir daí, as rotas com cadeado enviam o header sozinhas.
